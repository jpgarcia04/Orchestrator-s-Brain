# MSI de Brain en un runner Windows desechable

Base: `main` en `0c0365d14009d806226d40a260be44c8bfb7f147` (PR #7 fusionada). Esta PR añade un ensayo de instalación y desinstalación para el MSI generado por el mismo commit que ejecuta el workflow. No usa la bóveda personal, no instala en el equipo principal y no publica el paquete.

## Alcance y límites del entorno

El job usa `windows-2022`, un runner **hospedado por GitHub**. GitHub documenta que los runners Windows se ejecutan como administradores con UAC desactivado y que cada job normal recibe una VM nueva. Eso permite probar cambios de Windows Installer en un sistema que se desecha al terminar, pero no demuestra que haya un escritorio interactivo utilizable. La imagen y sus herramientas cambian con el tiempo. Se registran su versión, sistema operativo, Node, Rust y commit en la ejecución. Fuentes: [runners hospedados](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [imágenes Windows](https://github.com/actions/runner-images/blob/main/images/windows/Windows2022-Readme.md).

`msiexec` admite `/i` para instalar, `/x` para desinstalar, `/qn` para no mostrar UI, `/norestart` para evitar reinicio y `/L*V` para registro detallado. Sus códigos de salida son parte del resultado observado; `3010` señala que hace falta reiniciar y no se acepta como prueba de instalación completa en este job. Fuente: [Microsoft, msiexec](https://learn.microsoft.com/windows-server/administration/windows-commands/msiexec).

El MSI de Tauri puede descargar y ejecutar el bootstrapper de WebView2 si falta el runtime. El script lee la tabla `CustomAction`, la condición en `InstallExecuteSequence` y la versión registrada de WebView2 **antes** de instalar. Si el paquete declara esa acción y no consta el runtime, se detiene: no descarga el bootstrapper. Una clave de registro no acredita que WebView2 vaya a renderizar en la sesión del runner. Fuentes: [Tauri, instalador Windows](https://v2.tauri.app/distribute/windows-installer/), [Microsoft, distribución de WebView2](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution).

## Ejecución reproducible

El workflow `.github/workflows/validar-msi-windows.yml` se activa para esta PR y admite ejecución manual una vez que exista en la rama predeterminada. Tiene `contents: read`, checkout sin persistir credenciales, sin secretos, despliegues ni pasos de publicación. Usa `npm ci`, `npm run tauri -- build --ci --no-sign --bundles msi` y `cargo build --manifest-path core/Cargo.toml --locked --release -p obrain-api --bin obrain`. El MSI queda asociado al SHA del job; se guardan tamaño, SHA-256, firma, versión y `ProductCode`.

`tools/validar-msi-runner.ps1` sólo continúa si detecta un runner hospedado, token administrador, `msiexec` y ausencia de carpetas Brain en el perfil original del runner. Abre el MSI en modo lectura mediante Windows Installer COM e inspecciona propiedades, archivos, directorios, registro, accesos directos, acciones personalizadas, secuencia y ausencia de `ServiceInstall`. Verifica producto, `ALLUSERS=1`, carga `obrain-app.exe` y `DirectML.dll`, y destino `ProgramFiles64Folder` antes de instalar.

La biblioteca de PR #7 se copia a una raíz nueva bajo `%TEMP%` con `tools/biblioteca-sintetica.ps1` y se comprueban sus 11 archivos. La CLI del mismo commit registra sólo esa biblioteca en una base cifrada dentro de un perfil sintético. Su salida se suprime para no exponer la clave de recuperación. Para el arranque de la aplicación instalada, el proceso hijo recibe `OBRAIN_DB`, `USERPROFILE`, `HOME`, `APPDATA`, `LOCALAPPDATA`, `TEMP`, `TMP` y `WEBVIEW2_USER_DATA_FOLDER` dirigidos a esa raíz. Se comprueba que no aparecen `.obrain` en las dos ubicaciones originales del runner. **Esto comprueba rutas configuradas y escrituras visibles; no hay una traza completa de lecturas de archivos.**

El script ejecuta `msiexec /i` y espera a que termine. Para aprobar la instalación exige código 0, `ProductState=5`, entrada de desinstalación con nombre y ruta correctos, los dos binarios y la clave HKCU con `InstallDir` correcto. Intenta iniciar el ejecutable durante 20 segundos y exige que el proceso arranque, siga vivo y conserve la base sintética; registra también su sesión y los datos del perfil WebView2. En `finally`, lo cierra e intenta `msiexec /x` incluso si una comprobación falla. Para aprobar la retirada exige código 0, `ProductState=-1` y ausencia de entrada de desinstalación, ambos binarios y el valor HKCU `InstallDir`. Guarda `resultado.json` y los logs detallados de MSI como artefacto del job durante siete días. No sube la base, su llave, la fixture copiada ni el perfil WebView2.

El inspector PowerShell falló al descomponer las filas COM de la tabla `Property` (`Cannot index into a null array`); `msiexec /i` **no se ejecutó**. El artefacto contiene sólo `resultado.json`, sin logs de instalación. La lectura de filas se corrigió en `878668d`.

La [tercera ejecución](https://github.com/jpgarcia04/Orchestrator-s-Brain/actions/runs/38447401936), sobre `878668d`, pasó las dos compilaciones y el preflight completo. WebView2 `131.0.2903.86` ya estaba registrado, por lo que la acción condicional de descarga no era necesaria. La CLI creó una base cifrada con los 11 documentos sintéticos; no se subieron la base ni su llave.

En esa ejecución, `msiexec /i` devolvió **0** y el log dice `Installation completed successfully`; registra `INSTALLDIR=C:\Program Files\Orchestrator's Brain\`, copia a `C:\Windows\Installer` y cuatro valores en `Software\obrain\Orchestrator's Brain`. El comprobador buscó inmediatamente una entrada de desinstalación bajo las vistas HKLM habituales y no la halló, por lo que se detuvo **antes** de comprobar archivos instalados o arrancar la app. Su bloque `finally` llamó `msiexec /x {ProductCode}`: devolvió **0** y el log dice `Removal completed successfully`, incluida la retirada de esos valores. La ausencia posterior de ejecutable y entrada de desinstalación se registró, pero el primero no había sido confirmado antes de desinstalar. La comprobación se cambió para consultar el estado oficial de Windows Installer y revisar también HKCU; la presencia de la entrada de desinstalación queda como observación independiente.

El script ahora consulta el estado con un objeto COM nuevo tras una breve espera y lo guarda como dato, sin dejar que esa única señal impida las comprobaciones de archivos, registro y arranque.

El informe marcó como ausentes ambos binarios tras `msiexec /i` y no intentó arrancar la app. La comparación de marcas de tiempo del artefacto mostró la causa: el script continuó mientras Windows Installer seguía activo. Compiló MSI y CLI. El preflight confirmó token administrador, Windows Installer disponible, ausencia de las dos rutas Brain originales en el perfil del runner y WebView2 registrado (`131.0.2903.86`). La CLI creó la base cifrada usando sólo los 11 archivos sintéticos.

`msiexec /i` terminó con código **0** y el log indica instalación completa. El bootstrapper de WebView2 se omitió por su condición; no se descargó. Tras esperar a `msiexec`, existían `C:\Program Files\Orchestrator's Brain\obrain-app.exe` (44.697.088 bytes; SHA-256 `37DB320ABA941F4EB38A35AE4757643DDA3FC4735A7D14C45939F54C38F3A13E`) y `DirectML.dll` (18.527.776 bytes). `Installer.ProductState` devolvió **5** (instalado). La entrada de desinstalación figuraba con nombre y ubicación correctos, y la clave HKCU de Brain contenía `InstallDir` y los tres indicadores de accesos directos.

El script arrancó el ejecutable instalado con la base y el perfil sintéticos. El proceso seguía vivo a los 20 segundos, en sesión 2; la base seguía presente y se observó una entrada en el perfil aislado de WebView2. Las dos rutas Brain originales del runner seguían ausentes. **No se observó una ventana ni se recorrió la interfaz.** Esta prueba tampoco incluye una traza de lecturas del proceso, por lo que no acredita ausencia total de accesos a otras rutas.

Después de cerrar el proceso, `msiexec /x` terminó con código **0** y el log indica retirada completa de ambos archivos. `Installer.ProductState` devolvió **-1** (producto desconocido); no quedó la entrada de desinstalación, el ejecutable ni el valor `InstallDir` en HKCU. El artefacto de la ejecución contiene `resultado.json`, `msi-install.log` y `msi-uninstall.log`, sin la base, la llave ni los archivos sintéticos.

Las dos ejecuciones correctas anteriores a esta revisión registraron el estado del producto, la entrada de desinstalación y la supervivencia del proceso sin exigirlos como condiciones de éxito. El script ahora los exige; los resultados de aquellas ejecuciones siguen siendo evidencia observada, pero no sustituyen la ejecución de los criterios reforzados.

## Lo que el ensayo no acredita

Un proceso arrancado no equivale a una ventana dibujada. No se ejecutan clics, capturas ni los ocho recorridos visuales de `docs/VALIDACION-PRODUCTO-WINDOWS.md`. Tampoco se prueba un instalador firmado, actualización de versión, otras ediciones de Windows, perfiles reales, búsqueda semántica con modelo, lectura exhaustiva de rutas por el proceso, ni ausencia de efectos de Windows Installer fuera de las ubicaciones inspeccionadas. El runner se desecha al terminar.
